# Private member booking-history archive

The signed-in member can open `/dashboard/bookings/history` from the customer dashboard or My Bookings **Past** tab. This is a private, read-only, server-rendered archive designed for accounts with long booking histories. It supplements the existing My Bookings management page instead of changing the existing live reschedule, cancellation, review, payment or refund workflows.

The historical filter includes bookings whose **scheduled start time is in the past**, plus `COMPLETED` and `CANCELLED` bookings regardless of start time. It excludes future active sessions. Past unfinalized bookings appear with their saved status rather than being falsely labelled completed. The page filters by All history, Completed or Cancelled, and has a case-insensitive service-name search (max 80 characters). It sorts by session time descending with a stable ID tie-breaker. Pages display 20 rows and clamp requested page values to the last existing page, with a maximum of page 1000 to avoid extreme database offsets. Empty and no-results states include navigation back to current bookings. Timestamps are explicitly formatted in Asia/Kolkata (IST). Historical entries contain service, practitioner, start, duration and status only; **no meeting URL, member contact details or payment tokens are rendered**.

The same filters can be used with authenticated `GET /api/bookings/history/export?status=completed&q=...` to download a UTF-8 CSV with a BOM. The exporter always enforces the session's `userId` on the server. It limits output to 1000 matching records and returns HTTP 413 with a clear filtering suggestion for larger exports instead of silently truncating the report. Duplicate, unknown or oversized filters return HTTP 400. It quotes CSV data correctly and guards against spreadsheet formula injection. The export includes booking reference, service, practitioner, UTC start, duration, status; it does not include user contact data, payments, refund amounts or meeting links. Successful and error responses are private/no-store.

Testing covers filter parsing and safe links, owner-scoped queries, navigation and page bounds, safe CSV escaping, and real database fixtures containing future, completed, cancelled, other past and foreign-owned bookings. Existing management actions remain independently protected by server-side ownership and optimistic-version rules.

**Scope limitation:** the existing interactive `/dashboard/bookings` page still loads its booking list in the browser to offer management dialogs. This work provides a separate bounded history path; it does not yet replace that interactive list with fully server-paginated live booking management. That additional refactor will require coordinating its client state, deep links and review flows.

No schema migration, new provider secret, email send, booking mutation or data reconciliation occurs. Roll back by removing the history page/export/helper and dashboard/history links without altering any appointment records.
